# 采访事实核查工作台（Interview Fact-Check Workbench）

一个可 **Docker Compose 一键启动** 的采访事实核查工具：粘贴带时间戳的采访文字 → 选取片段建立**事实主张**并关联**证据摘录** → 系统自动**规范化主张**并提示**互相矛盾的说法** → 展示每条主张的**证据链与审核状态** → 编辑原文后自动**追踪证据定位影响**（唯一匹配自动更新、无/多匹配进入待确认队列） → 一键导出**含时间戳引用、区分当前定位与历史快照的 Markdown 核查报告**。

## 技术栈

- **后端**：Node.js 20 + Express
- **数据库**：SQLite（`better-sqlite3`，数据文件持久化到 Docker 卷）
- **前端**：原生 HTML/CSS/JavaScript，无需构建
- **矛盾检测**：内置的中文文本规范化 + 数值事实抽取 + 相似度/否定判定（规则引擎，无需外部 API 或大模型）

## 一键启动

前置要求：已安装 Docker 与 Docker Compose（v2）。

**单条命令启动（构建并后台运行）：**

```bash
docker compose up -d --build
```

启动后浏览器访问：

```
http://localhost:3000
```

> 首次构建需要编译 `better-sqlite3` 原生模块，可能耗时数分钟；之后启动只需数秒。

停止 / 查看日志：

```bash
docker compose down            # 停止（保留数据）
docker compose logs -f         # 查看日志
```

## 端口与配置

所有配置通过环境变量完成，在 `docker-compose.yml` 中修改：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务监听端口（容器内）。修改宿主机映射请改 `ports` 左侧，如 `"8080:3000"` |
| `DB_PATH` | `/app/data/factcheck.db` | SQLite 数据库文件路径 |

数据持久化：Compose 中声明了命名卷 `factcheck-data` 挂载到 `/app/data`，容器删除/重建后采访、主张、证据与审核记录均不丢失。

本地非 Docker 运行（需 Node.js ≥ 20）：

```bash
npm install
npm start
# 数据库默认写入 ./data/factcheck.db
```

## 使用流程

1. **新建采访**：点击「＋ 新建采访」（或「载入示例文稿」快速体验），粘贴带时间戳的文字。
   支持的时间戳格式：
   - `[00:01:23]`、`(12:34)`、`00:01:23：`、`1:23：`（两段时按 分:秒 处理）
   - `【2分15秒】`
   - 无时间戳的续行会并入上一段；完全无时间戳时作为整体一段处理
   - 行首的说话人前缀 `张三：……` 会被自动识别
2. **建立事实主张**：在左侧原文上**划选文字**，弹出工具条后选择「建立事实主张」，可编辑规范化表述；所选原文自动成为第一条证据（带时间戳与说话人）。
3. **关联证据摘录**：划选其它片段后选择「追加为证据」，关联到已有主张，形成完整**证据链**。
4. **自动规范化与矛盾提示**：保存主张时，系统会：
   - 全角转半角、中文数字（含「两百三十」「两亿」「二零二三年」等）转阿拉伯数字；
   - 抽取数值事实（日期、金额、百分比、年龄、时长、面积、距离、重量、人数/次数等计数）；
   - 判定肯定/否定极性；
   - 同一采访内对主张两两比较，给出 **数值冲突**、**肯定/否定冲突**、**疑似重复** 三类提示。误报可点击「忽略」。
5. **审核状态**：每条主张可标记为 `待核实 / 已证实 / 已证伪 / 有争议 / 已更正`，并填写审核备注。
6. **修订原文与证据影响追踪**：点击「✏️ 编辑原文」保存修改后，系统重新分段，并将**已有证据摘录与新分段自动重新匹配**（依据：摘录文本 + 时间戳 + 说话人）：
   - **唯一匹配**：自动更新证据定位（即使时间戳被移动、分段顺序变化也能跟上）；
   - **无匹配**（片段被删除/改写）或 **多匹配**（相同内容在新原文中出现多处、锚点无法区分）：证据标记为 **「待确认」**——绝不静默丢失，也绝不猜测迁移；
   - 页面顶部出现 **待确认队列横幅**，受影响的**主张卡片显示「N 条待确认」角标**（侧栏采访列表同样有标记）；
   - 对每条待确认证据可选择：**重绑到某个新片段**（候选片段优先列出，也可从全部片段中选择；重绑后说话人/时间戳同步更新），或**保留为历史快照**（保留修订前的摘录与原定位说明，不再指向当前原文、也不再参与后续重匹配）；
   - 待确认全部处理完后横幅消失，工作台恢复正常状态。
7. **导出报告**：点击右上角「导出核查报告」，生成 Markdown 报告，包含矛盾清单、每条主张的规范化表述/抽取事实/状态/审核备注，以及证据链——其中明确区分 **当前定位证据（编号列表）、待确认证据（⚠️ 标注原因与原定位）、历史快照证据（🗄️ 标注为修订前内容）**——另附原文时间轴；可在线预览、复制或下载 `.md`。

### 修订匹配规则说明

- 文本比对忽略所有空白差异（换行、多空格、全角空格），摘录允许跨多个连续分段（划选跨段证据时）；
- 时间戳与说话人作为消歧锚点：同一文本多处出现时，锚点唯一吻合者自动更新，否则进入待确认；
- 无时间戳分段使用的「片段 N」仅为展示标签，不作为时间戳锚点（避免按段号错配）；
- 已标记为**历史快照**的证据在之后任何修订中都保持不变。

## 数据与接口

主要 REST API（JSON）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/interviews` | 采访列表（含主张/矛盾计数） |
| POST | `/api/interviews` | 新建采访并解析全文 |
| GET | `/api/interviews/:id` | 采访详情（分段、主张、证据、矛盾、待确认证据计数） |
| PUT | `/api/interviews/:id` | 更新原文（重新分段、证据重匹配、重算矛盾；响应含 `rematch_summary`） |
| DELETE | `/api/interviews/:id` | 删除采访 |
| POST | `/api/interviews/:id/claims` | 建立事实主张（可附带证据，支持 `seg_ord` 定位） |
| PUT | `/api/claims/:id` | 更新主张文本 / 审核状态 / 备注 |
| DELETE | `/api/claims/:id` | 删除主张 |
| POST | `/api/claims/:id/evidence` | 追加证据摘录（支持 `seg_ord` 定位） |
| DELETE | `/api/evidence/:id` | 删除证据 |
| PUT | `/api/evidence/:id/resolve` | 处理待确认证据：`{"action":"rebind","seg_ord":N}` 重绑到新片段，或 `{"action":"snapshot"}` 保留为历史快照 |
| PUT | `/api/contradictions/:id/ignore` | 忽略/恢复矛盾提示 |
| GET | `/api/interviews/:id/report` | 下载 Markdown 核查报告（区分当前定位 / 待确认 / 历史快照证据） |

## 目录结构

```
.
├── docker-compose.yml      # 一键启动
├── Dockerfile              # 多阶段构建（含 better-sqlite3 原生编译工具链）
├── package.json
├── server/
│   ├── index.js            # Express 服务与 API 路由
│   ├── db.js               # SQLite 连接、表结构与轻量迁移
│   ├── parser.js           # 时间戳/说话人解析与分段
│   ├── rematch.js          # 原文修订后的证据重匹配（文本/时间戳/说话人）
│   ├── normalizer.js       # 规范化、事实抽取、矛盾检测
│   └── report.js           # Markdown 核查报告生成
└── public/
    ├── index.html
    ├── app.css
    └── app.js
```

## 说明与限制

- 矛盾检测为**确定性规则引擎**，适合快速发现数字/日期不一致与“是/否”直接对立；语义级的复杂矛盾可能漏报，也可能出现误报，可使用「忽略」处理。
- 比对范围为**同一采访内**的主张；跨采访比对不在当前版本范围内。
